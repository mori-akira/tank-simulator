# ドキュメント整合性チェック

`CLAUDE.md` と `docs/` 配下、および実際のリポジトリの状態を突き合わせ、**不整合を検出して報告する**。

## 重要な制約

**検出するだけで、修正はしない。** 修正するかどうか、どちらを正とするかはオーナーが決める。ドキュメントには意図が込められているため、AI が良かれと思って書き換えると、その意図が失われる。

## 検査観点

以下の4点のみを見る。**観点を増やさないこと。** このスキル自体が肥大化すると、検査の焦点がぼやける。

### 1. ドキュメント間の矛盾

同じ事柄について、複数のドキュメントが異なることを述べていないか。

### 2. 実態との乖離

記載内容がリポジトリの実際と一致しているか。

- 記載された `npm run *` コマンドが `package.json` に存在するか
- 記載されたディレクトリ構成が実際の構成と一致するか
- 記載された技術スタックが `package.json` の依存と一致するか

### 3. リンク切れ

Markdown の相対リンクの参照先が実在するか。

### 4. 記述の重複

同じ内容が複数箇所に書かれていないか。今は一致していても、片方だけ更新されて将来の矛盾になる。単一の出典に集約すべき箇所を指摘する。

## 手順

1. `CLAUDE.md` と `docs/` 配下の全 Markdown を読む
2. `package.json`、実際のディレクトリ構成を確認する
3. 上記4観点で突き合わせる
4. 報告する

## 報告形式

観点ごとに、検出した箇所と判断材料を示す。指摘がなければ「指摘なし」と述べる。**問題を作り出さないこと。**

```
### 1. ドキュメント間の矛盾
- docs/a.md:12 と CLAUDE.md:30 — 前者は X、後者は Y と記述。
  実装は X に従っているため、CLAUDE.md 側が古い可能性が高い。

### 2. 実態との乖離
- 指摘なし
```

最後に、**どれを優先して直すべきか**を1〜2行で述べる。すべてが同じ重要度ではない。
