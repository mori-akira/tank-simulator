# 0005. 守るべき条件は文章ではなくハーネスで強制する

## 背景

[CLAUDE.md](../../CLAUDE.md) の「変更禁止の土台」3件と、コミット前に `npm run verify` を通す決まりは、いずれも**文章として書かれているだけ**だった。

文章は「守られることを期待する規約」であって、強制力を持たない。実際 [Issue #9](https://github.com/mori-akira/tank-simulator/issues/9) の時点で、`verify` の実行を忘れれば壊れたコードが `main` に入る状態だった。

AI駆動開発では、この差が通常のプロジェクトより大きく効く。セッションは毎回コールドスタートであり、指示を読み落とすことも、読んだうえで「今回は軽微だから」と省くこともある。**そして守られなかったことを、オーナーは事後に確認する手段を持たない**（コードを読まないため）。

## 決定

`CLAUDE.md` と `docs/` に書いた条件のうち、**機械的に検査できるものはハーネス側の機構で強制する。** 文章はその理由を残す場所であって、強制の手段としては扱わない。

この方針が対象とするのは、「変更禁止の土台」3件（層の依存方向 / 決定論 / ロジック2D・描画3D）と、コミット前の `verify` である。どこまで機構化できているかはリポジトリの設定ファイルと Issue が示す。

## 理由

**指示は強制力を持たない。** これは推測ではなく、#9 以前の状態で実証されている。

**機構は沈黙して失敗しうる。** だから機構を入れるときは、違反を意図的に作って**実際に落ちることを確認する**。[ADR 0004](0004-typescript-6-for-depcruise.md) で、TypeScript 7 では層検査が「0 modules cruised」で成功してしまう罠を踏んでいる。通ったことは、守られたことを意味しない。

**決定論は優先度が高い。** これが破れるとリプレイのハッシュ比較が成立せず、「挙動を1ビットも変えずにリファクタした」ことを証明する手段が失われる。検証の土台そのものが崩れるため、他の条件より先に機構化する価値がある。

## 検討した代替案

**`.git/hooks/`** — git の管理外にあり、clone しても付いてこない。環境ごとの手作業を前提とする仕組みは、忘れられた時点で無音で失効する。

**CI のみ** — `main` 直コミット運用では検知が事後になる。GitHub Actions が落ちた時点で、壊れたコミットは既に `main` にある。

**文章での指示を強める** — #9 以前の状態そのもの。効かなかったことが実証済み。

## 機構を外すとき

**「遅い」は外す理由にならない。** 外す判断をする前に、その条件が破れたときに何が壊れるかを確認すること。機構は、それが守っている条件がまだ必要である限り必要である。
