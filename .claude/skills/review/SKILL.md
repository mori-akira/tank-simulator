# 客観レビュー

差分を **`code-reviewer` サブエージェント**に渡してレビューさせる。サブエージェントはコールドスタートであり、実装セッションの思い込みを引き継がない。ここが「自分で自分をレビューしても同じ思い込みを二度通すだけ」を避ける唯一の仕掛けなので、**自分でレビューして済ませないこと。**

## 手順

### 1. 対象の差分を決める

引数があればそれに従う。無ければ以下の順で決める。

1. `git status --short` に何か出れば、それが対象。追跡済みの差分は `git diff HEAD`、**未追跡ファイル（`??`）は差分に出ないので Read で全文を読ませる**
2. 何も出なければ直近のコミット `git show HEAD`

**`git diff HEAD` だけを渡さないこと。** 新規ファイルが主体の変更でそれをやると、レビュアーは空の差分を読んで「指摘なし」と返す。レビューを実行した記録だけが残り、実際には何も読まれていない状態になる。

対象が空なら、レビューせずにその旨を伝えて終わる。

### 2. サブエージェントを起動する

Agent ツールで `subagent_type: "code-reviewer"` を起動する。プロンプトには**対象の指定と、差分を自分で取得するためのコマンド**を書く。差分の中身を貼り付けない（サブエージェントは自分でリポジトリを読める）。

`code-reviewer` を起動できない場合は、**別のエージェントで代用せず、その旨をオーナーに伝えて止まる。** 代用すると「レビュアー定義に従っていない別モデルが走った」ことを検知できなくなり、レビューした記録だけが残る。

### 3. 結果を報告する

サブエージェントの報告はオーナーには見えない。**指摘をそのまま伝える。** 要約して弱めない。

「要対応」の指摘には、自分の見立て（同意する / しない、その理由）を添える。**レビュアーが間違っていることもある。** 鵜呑みにせず、指摘が実在することを自分で再現してから同意する。

再現して確かめられた自分のミスは、報告したうえでその場で直してよい。**見解が分かれるもの、仕様に関わるもの、スコープが広がるものはオーナーに回す。**

## やらないこと

- レビュアーに修正させない。判定と実装は分ける
- `npm run verify` が検査済みのもの（型・lint・層の依存方向・`Math.random()`）を再レビューさせない
- コミットをブロックしない。強制しない判断は [ADR 0006](../../../docs/adr/0006-no-forced-review-gate.md) にある
